# Manifest reference

Every Capell package ships a `capell.json` file at its root. The tables below cover every top-level key read by `CapellManifestData` for manifest version 3.

Use the [JSON Schema](../../packages/core/resources/schema/capell-manifest-v3.schema.json) for field types, allowed values and object shapes. Add `"$schema": "https://capell.app/schema/capell-manifest-v3.schema.json"` to `capell.json` to enable editor completion. The tables also include the editor’s optional `$schema` metadata.

The **Required** column describes valid manifests. The **Default** column shows what Capell uses when an optional key is absent. Required fields must be supplied. For a working example, see [Package anatomy](package-anatomy.md#capell-manifest).

## Identity

| Key                | Required | Type           | Default                              | Allowed values and purpose                                                                                                                                          |
| ------------------ | -------- | -------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$schema`          | No       | string         | —                                    | Points editors to the JSON Schema.                                                                                                                                  |
| `manifest-version` | Yes      | integer        | —                                    | Identifies the manifest format. The only allowed value is `3`.                                                                                                      |
| `name`             | Yes      | string         | —                                    | The Composer package name, such as `acme/capell-gallery`. It must match `name` in the package's `composer.json`.                                                    |
| `slug`             | Yes      | string         | —                                    | Short package identifier. Use at least two lowercase letters, digits or hyphens, starting and ending with a letter or digit.                                        |
| `displayName`      | Yes      | string         | —                                    | Non-empty name shown in the installer, the admin Extensions page and Marketplace.                                                                                   |
| `kind`             | Yes      | string         | —                                    | Classifies the extension as `package`, `plugin`, `theme`, `integration` or `bundle`.                                                                                |
| `capellApiVersion` | Yes      | string         | —                                    | The Composer version constraint for the Capell extension API the package supports. See [Extension API versioning](extension-api-versioning.md).                     |
| `version`          | Yes      | string         | —                                    | The package version as a non-empty string.                                                                                                                          |
| `description`      | No       | string         | `null`                               | One-line description shown with the package.                                                                                                                        |
| `documentationUrl` | No       | string         | Composer `support.docs`, then `null` | URI for the package documentation, stored on the package registry entry.                                                                                            |
| `visibility`       | No       | string         | `"catalogue"`                        | Use `catalogue` to list the package as a product choice or `support` to hide it as a standalone choice while allowing installation through `dependencies.supports`. |
| `launchStatus`     | No       | string         | `"shipped"`                          | Use `shipped` for a released package, `preview` to list it with a Preview badge, or `hidden` to keep it off every public listing until it is ready. |
| `namespace`        | No       | string or null | `null`                               | Root PHP namespace, such as `Acme\Gallery\`. Consumers of the resolved namespace can infer it from the first suitable provider class.                               |
| `product`          | Yes      | object         | —                                    | `group`, `tier` (`free`, `premium` or `core`) and an optional `bundle`. See [Package product groups](product-groups.md).                                            |

## Runtime and loading

| Key            | Required | Type            | Default                            | Allowed values and purpose                                                                                                                                                                                                               |
| -------------- | -------- | --------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `surfaces`     | Yes      | list of strings | —                                  | The surfaces the package takes part in: `content`, `admin`, `frontend`, `workflow`, `delivery`, `operations`, `integrations`, `marketplace`, `console` or `shared`.                                                                      |
| `dependencies` | Yes      | object          | —                                  | `requires`, `supports` and `conflicts`, each a list of Composer package names. See [Package anatomy](package-anatomy.md#capell-manifest).                                                                                                |
| `providers`    | Yes      | object          | —                                  | Service provider classes in the buckets `metadata`, `install`, `runtime`, `auth`, `admin` and `frontend`. Every bucket except `auth` must be present. See [Lifecycle provider buckets](service-providers.md#lifecycle-provider-buckets). |
| `runtime`      | No       | string          | `"blade"`                          | Runtime label used by the package capability graph, which recognises `livewire`. The field accepts a string.                                                                                                                             |
| `scopes`       | No       | list of strings | `[]`                               | `backend`, `frontend` or both. Capell copies them to the package registry entry. Use `surfaces` to declare runtimes; most packages leave `scopes` out.                                                                                   |
| `order`        | No       | integer         | `0`                                | Sets the package sort position in the registry.                                                                                                                                                                                          |
| `installPath`  | No       | string or null  | Composer install path, then `null` | Internal package filesystem location. The install path passed to the loader takes precedence. Leave this key out of authored manifests.                                                                                                  |

## Lifecycle

| Key               | Required | Type            | Default                               | Allowed values and purpose                                                                                                                                                                                                                            |
| ----------------- | -------- | --------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `actions`         | No       | object          | Empty map                             | Class-strings implementing `PackageLifecycleAction` for `install`, `uninstall`, `setup` and `afterInstall`. A web-triggered install needs these. See [Lifecycle: actions and commands](build-extension-end-to-end.md#lifecycle-actions-and-commands). |
| `commands`        | No       | object          | Empty map                             | Legacy artisan command names for lifecycle phases, plus `doctor`, which `capell:doctor` runs. Web-triggered installs refuse a package that declares only `commands`.                                                                                  |
| `database`        | No       | object          | Empty map                             | `migrations` and `settings` (booleans) say whether installing runs migrations or settings migrations; `requiredTables` lists tables the readiness report checks for.                                                                                  |
| `install`         | No       | object          | Empty `tips` and `legacyTables` lists | `tips` shown in the hand-off at the end of an install, and `legacyTables` the installer's table-collision check treats as belonging to this package.                                                                                                  |
| `demo`            | No       | boolean         | `false`                               | Marks a demo-content package for selection when demo content is requested.                                                                                                                                                                            |
| `defaultSelected` | No       | boolean         | `false`                               | Preselects the package in the installer.                                                                                                                                                                                                              |
| `roles`           | No       | list of strings | `[]`                                  | Jobs the package performs for Core, so Core finds it by role instead of by name: `default-theme`, `workflow-final`, `developer-tooling`, `site-social-fields` or `scaffold-full-profile`.                                                             |
| `rolePriority`    | No       | integer         | `0`                                   | Breaks ties between packages that share a role. Lower values sort first.                                                                                                                                                                              |

## Contributions and contracts

| Key                        | Required    | Type                                | Default            | Allowed values and purpose                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | ----------- | ----------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `contributes`              | Yes         | list of objects                     | —                  | Each extension contribution the package registers, such as a page type, content widget or route. See [Extension point API reference](extension-point-api-reference.md).                                                                                                                                                                                                                                                              |
| `contributionTraceability` | No          | object or empty list                | `null`             | Maps declared contributions to runtime wiring for `capell:extension-audit`. Use `contributions`, `deferredContributions` and `runtimeIntegrations` inside the object.                                                                                                                                                                                                                                                                |
| `settings`                 | No          | list of strings                     | `[]`               | Settings classes the package owns.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `permissions`              | No          | list of strings                     | `[]`               | Permission names the package defines. Admin permission sync creates them.                                                                                                                                                                                                                                                                                                                                                            |
| `capabilities`             | No          | list of strings                     | `[]`               | Capability names the package offers; `capell:extension-audit` reports names Core does not know.                                                                                                                                                                                                                                                                                                                                      |
| `capabilityContracts`      | No          | object                              | `null`             | `provides` and `consumes`, each mapping a Core capability contract to the major version used. See [Capability contracts](package-anatomy.md#capability-contracts-between-optional-packages).                                                                                                                                                                                                                                         |
| `healthChecks`             | Yes         | list of objects                     | —                  | Each has `key`, `label` and `class`; the class implements `ChecksExtensionHealth`. Use `[]` when the package has none.                                                                                                                                                                                                                                                                                                               |
| `agent_tools`              | No          | list of objects, `"none"` or object | No tools or waiver | Tools an AI agent may run. Each declaration has `name` (a lowercase dotted identifier), `description` or `descriptionKey`, `inputSchema`, `outputSchema`, `effect` (`read` or `write`), `binding` (`type` and `target`) and an optional `ownerPackage`. `"none"` with `agent_tools_reason` declares that the package has no such tools. The object forms `{"tools": [...]}` and `{"none": true, "reason": "..."}` are also accepted. |
| `agent_tools_reason`       | Conditional | string                              | `null`             | Explains why the package offers no agent tools. A non-blank string is required when `agent_tools` is `"none"`. The object waiver uses its own `reason`.                                                                                                                                                                                                                                                                              |

## Themes

| Key        | Required | Type           | Default | Allowed values and purpose                                                                                                                   |
| ---------- | -------- | -------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `themeKey` | No       | string or null | `null`  | The theme's key. `capell:extension-audit` reports an error for a theme without one. See [Creating custom themes](creating-custom-themes.md). |
| `extends`  | No       | string or null | `null`  | The Composer name or theme key of a parent. Capell adds the parent's views after the child's and fails if the parent is missing.             |

## Safety, performance and privacy

| Key           | Required | Type   | Default            | Allowed values and purpose                                                                                                                                                                                    |
| ------------- | -------- | ------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `security`    | No       | object | `null`             | `riskTier`, `publicSurface`, `sensitiveData`, `publicOutput`, `externalHttpClients`, `throttles`, `manual` and `adminSurface`: what the package exposes, for `capell:extension-audit` and Marketplace review. |
| `performance` | Yes      | object | —                  | `frontendRenderBudgetMs`, `adminQueryBudget`, `cacheTags` and `cacheSafety`. See [Manifest values and cache safety](package-anatomy.md#manifest-values-and-cache-safety).                                     |
| `privacy`     | No       | object | Empty purposes map | Maps the names in `purposes` to `functional`, `preferences`, `analytics` or `marketing`. See [Consent purposes](package-anatomy.md#consent-purposes).                                                         |

## Marketplace

| Key           | Required | Type   | Default | Allowed values and purpose                                                                                                                                                                                                        |
| ------------- | -------- | ------ | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `commercial`  | Yes      | object | —       | `proposedLicense`, `requestedCertification`, `supportPolicy` and `privateDocsRequested`. Use the licence, certification and support policy values listed in the schema. Marketplace review decides the licence and certification. |
| `marketplace` | Yes      | object | —       | Provides listing copy and media through `summary`, `categories` and `screenshots`, with optional `problem`, `outcome` and `faq`. Set `hidden` to `true` to hide the listing. It defaults to `false`.                              |

## Keeping this page complete

`ManifestReferenceTest` compares the documented and schema keys with the validator's accepted keys and checks the schema properties against the keys read by `CapellManifestData::fromArray()`. Update the reference and schema alongside any change to the manifest fields. Keep the editor's `$schema` pointer in the schema's metadata pattern.
